# Spec — Frontend localization (i18n)

Part of [epic](../epics/nextcloud-web-app.md).

## Summary

All user-facing frontend text is hardcoded English today. This feature routes it
through Nextcloud's localization stack so the web UI can be shown in the user's
language. Three languages ship: **en** (source), **German (`de`)**, and
**Ukrainian (`uk`)**.

## Background — how Nextcloud localization works

- The **server** decides the language per request: the logged-in user's language
  preference (Settings → Personal → Language), falling back to the instance
  default, then the browser's `Accept-Language`. The client does not select a
  locale per request.
- `Util::addTranslations($appId)` makes the server serve
  `apps/<app>/l10n/<language>.js`, which calls `OC.L10N.register(...)` and
  populates `globalThis._oc_l10n_registry_translations`.
- `@nextcloud/l10n` `t()` / `n()` read that registry; if a key is missing they
  fall back to the English source string.
- Translation files live in `l10n/<lang>.json` (canonical) and
  `l10n/<lang>.js` (generated runtime bundle).
- The navigation label is translated too: `NavigationManager` calls
  `$l->t($nav['name'])` on the `info.xml` name, so `"Bye Bye Money List"` must be
  present in the app bundle.
- `uk` is a supported Nextcloud language (core ships `uk.json`).

## Requirements

- `templates/index.php` loads the app's translation bundle.
- A single app-bound helper module (`src/utils/l10n.ts`) exposes `t()`/`n()` so
  the app id is not repeated.
- Every frontend source string that is UI text is translated via `t()` /
  `n()`:
  - app shell (menu, shopping lists, catalog),
  - all dialogs,
  - catalog row/search components.
- Interpolated text uses named placeholders (`{name}`, `{count}`, `{query}`).
- Plurals use `n()` (Ukrainian needs three plural forms).
- Dates and numbers format with the user's locale
  (`getCanonicalLocale()`), not the browser default.
- Translations ship for `en`, `de`, `uk`, kept in `l10n/*.json`; runtime
  `*.js` bundles are generated by `npm run l10n`.
- A test guarantees the three bundles have identical key sets and that every
  source string is present in the source bundle.

## Scope

- **In:** frontend Vue/TS strings, plural + placeholder handling, locale-aware
  date/number formatting, navigation name, `en`/`de`/`uk` bundles, a JSON→JS
  compiler, parity/coverage tests.
- **Out:** PHP API response messages (they are not surfaced in the UI today),
  `info.xml` summary/description app-store localization, Transifex/`translationtool`
  `.pot` extraction, languages beyond `de`/`uk`, RTL-specific layout work.

## Design decisions

- **Server-resolved locale** — no client language switcher; the app follows the
  user's Nextcloud language, consistent with the rest of Nextcloud.
- **Manual JSON as the source of truth** — for three hand-maintained languages a
  small `scripts/l10n.mjs` compiles `l10n/<lang>.json` into the
  `OC.L10N.register(...)` runtime bundle, avoiding the Transifex/`translationtool`
  pipeline. The format stays compatible with that tooling for later use.
- **One helper module** — `src/utils/l10n.ts` binds the app id and re-exports
  `getCanonicalLocale`, so call sites stay short and the app id is defined once.
- **Full-sentence keys, not fragments** — e.g. the search summary is a dedicated
  key per tab (`Showing {visible} of {total} matching categories`) instead of
  concatenating a translated noun into an English sentence.
- **`t()` falls back to source** — English works without an `en` bundle; missing
  translations degrade to English rather than to a blank string.

## Constraints

- No backend/API/schema change and no `openapi.json` change.
- Must not break existing Vitest component tests (they assert English source
  text, which `t()` returns when no bundle is registered).
- `NcSelect`'s `label="name"` prop is an option field key, **not** UI text, and
  must not be translated.

## UI/UX considerations

- Language follows the user's Nextcloud setting automatically; no in-app switch.
- Placeholders in `NcTextField`/`NcSelect` are translated as UI text.
- Number/date examples in placeholders (`e.g. 1.5`) are translated too.
- Ukrainian plural rules: form 0 (1, 21…), form 1 (2–4, 22–24…), form 2 (0, 5–20,
  11–14…).
